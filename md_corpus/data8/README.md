# Data 8 Markdown corpus

Knowledge files for an LLM tutor. Everything here was generated by `nb2md.py`
or the PDF conversion scripts from upstream course material. Code output shown
in notebook-derived files was produced by executing the notebooks; nothing here
runs code.

## Layout

```
data8/
├── discussions/  discussion worksheets and staff solutions
├── tutoring/     tutoring worksheets and staff solutions
├── textbook/     Computational and Inferential Thinking chapters
├── homework/     one Markdown file per homework
├── project/      projects and checkpoint versions
├── exam/         current and archived exams
├── lab/          one Markdown file per lab
└── lectures/     lecture notebooks and live-coded variants
```

Assignment, lecture, discussion, and tutoring material in this snapshot is from
Spring 2026. The semester directory was flattened, but `semester: sp26` remains
in document front matter and source paths. Archived exams carry their original
term and year in their filenames and metadata.

Combined files (`hw.md`, `lab.md`, `project.md`,
`data8-sp26-textbook.md`, `data8-sp26-lectures.md`, and the worksheet
collections) duplicate content in the smaller files and are skipped by the
tutor index.

## How to read an assignment file

Front matter fields: `title`, `assignment`, `semester`, `source` (the
solution notebook), `student_source` (the notebook students actually receive),
`total_points`.

- **Student scaffold:** — the code cell exactly as the student sees it
  (usually `...` placeholders). This is what they start from; everything the
  scaffold already provides does not need to be written by the student.
- **Solution:** — the staff answer for that cell, with `# SOLUTION` markers.
  Never reveal solution code to a student directly; use it to guide them.
- **Code:** — provided code that is not a graded answer.
- **Test — `qN` (points)** — the otter-grader checks for that question, as
  `>>>` doctest lines. A case prefixed `# hidden test` is invisible to
  students until after grading, so a student's autograder can pass while a
  hidden case still fails.
- **## Datasets** — schema only (row count, column names/types) for each CSV
  the assignment loads. The data itself is not in this corpus: questions about
  actual values must be answered by running code, not from these files.

## How to read a textbook file

One file per chapter, `chNN_<slug>.md`. Sections are numbered headings
(`## 4.1 Numbers`); front matter lists the chapter's sections. Figures live in
`textbook/images/` (files named `chNN_sS_cellMMM_*.png` are plots the book
generates from code whose source is hidden from readers). Cite the textbook by
chapter/section number when pointing a student at background reading.

## How to read a lecture file

One file per lecture notebook: code, its actual printed/plotted output, and
prose exactly as presented in class — there is no student/solution split,
since lecture notebooks aren't graded. Front matter's `lecture` field is the
session (`lec14`); `variant` is set only for a notebook that isn't a
session's primary one — `live` for an in-class recording that may differ
from the planned notebook (extra debugging, a skipped example), or the
notebook's own stem for an unrelated demo dropped in that session's folder
(e.g. `monty_hall`). A `## Datasets` appendix lists the schema of any CSV
the lecture loads, same rules as assignments: run code for actual values.
